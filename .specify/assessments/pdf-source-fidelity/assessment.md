# Assessment: original-PDF source fidelity in the actual application

- Date: 2026-11-17 (UTC).
- Scope: independent static, read-only assessment of this application's source, dependencies, endpoints and existing evaluation evidence. The sole new artifact is this assessment. No implementation, install, model call, server, migration or production modification was performed. This is **not DSH tooling**.
- Evidence confidence: high for inspected application contracts; medium for negative discovery findings; **unknown for deployed provider vision capability**.
- This report is a requested assessment/recommendation, not a claim of completed PDF support or PDF-level acceptance.

## Executive recommendation

Keep the parent's bounded organization correction separate. Its text/HTML model path cannot repair mathematical evidence absent before organization. The smallest safe next increment is an **opt-in, upload-only source-fidelity capture**: retain immutable original PDF bytes privately, render ordered full-page images under strict resource limits, and persist a page/provenance manifest plus optional uncorrected text-layer output. Display original page evidence beside any derivative text; do not silently promote OCR HTML into an authoritative original. No manually supplied question grouping, repaired formulas, subject taxonomy or gold annotations should enter acquisition or the model input.

Do not first turn the current OCR endpoint into a general PDF importer: it lacks several necessary safety controls and discards source image provenance. First demonstrate byte/page fidelity offline with existing PDFs and malformed-input tests; wire authorized upload/read only after that contract passes. A later, separately authorized vision experiment can consume these same immutable page images if the configured provider is evidenced to support them. A page image preserves visible layout **at its recorded raster resolution**; it is not lossless vector/math extraction and not proof of correct OCR or segmentation.

## 4. Security and resource constraints

### Existing controls and gaps

- [Bank HTTP:5–18](</home/dsh/trangchugiaovien/lib/server/question-bank-http.ts#L5-L18>): database/authentication, origin check when supplied, JSON content type, streamed 12,000,000-byte body cap, owner-ID match and no-store response. [Bank store:12–27](</home/dsh/trangchugiaovien/lib/server/question-bank-store.ts#L12-L27>) scopes by owner, locks updates, admits at most two active banks, caps serialized bank state at 24,000,000 characters. [Bank limits](</home/dsh/trangchugiaovien/lib/question-bank/types.ts#L3-L3>) include 2,000,000 source characters, 200 sources, 2,000 questions, 200 context questions and 90 seconds of processing. These are **HTML/bank caps, not PDF decompression/raster caps**.
- [OCR route:30–66](</home/dsh/trangchugiaovien/app/api/exam-image/route.ts#L30-L66>) calls `req.json()` before size checks. It applies an estimated 8 MiB cap per image, but no aggregate/count/request streaming cap; no strict image MIME allowlist, base64-byte validation, decoded dimensions/pixel budget, or object-shape/array validation robust to arbitrary runtime JSON. The inspected route has no `requireUser`, origin validation, owner check or explicit endpoint rate/cost admission. Reverse-proxy/global protections were not established, so do not claim deployed anonymous exploitability or full absence of external protection. Do not copy these omissions into PDF support.
- [Private storage](</home/dsh/trangchugiaovien/lib/server/storage.ts#L23-L64>) validates lexical storage keys and writes outside public. It is not itself an authorization layer, quota service or atomic multi-artifact transaction. New routes must enforce ownership independently; do not accept raw object keys from clients as authority.

### Required for a bounded future increment (proposed, not implemented)

- Authenticate and validate same-origin mutation before processing; server chooses owner/source IDs and storage keys. Every original, manifest and page read checks source ownership. Cross-account request IDs or leaked storage keys must yield no data. No public URLs; private cache/no-store policy and safe download headers.
- Stream input into a capped private temporary object; do not buffer unbounded multipart/JSON first. Sniff/validate PDF structure, reject encrypted/password-protected unsupported documents and malformed content explicitly. A `%PDF` header alone is not proof of safety.
- Proposed initial hard ceilings: **20 MiB original, 30 pages, 150 DPI with maximum 2,048 pixels per edge and 4 megapixels per page, 80 megapixels total, 80 MiB derived output, 60 seconds wall time, 512 MiB worker memory, one worker per owner/two service-wide**. Values are a conservative starting hypothesis requiring fixture/resource validation, not measured safe production settings. Reject the whole ingest on cap breach; no silent page truncation or partial-success claim. Page/pixel caps apply before allocating huge raster surfaces where feasible; worker process/container caps remain necessary even for header inspection.
- Run a patched PDF renderer as an unprivileged isolated worker, no network, no secrets, read-only runtime, private temp output, hard process/time/memory/file-count limits, fixed executable/argument arrays (no shell interpolation), bounded diagnostics, kill on cancellation. Disable/ignore active PDF JavaScript, actions, embedded files and external references; never execute document instructions. Handle zip/decompression/object bombs and pathological page dimensions. Delete only verified owned temp paths; atomic manifest publish and cleanup/retention accounting must cover failure/crash.
- PDF text, annotations, filenames, OCR output and model replies are **untrusted data**. Prompt explicitly separates instructions from document evidence. Never obey document prompts; never fetch embedded links; never execute LaTeX/script/HTML supplied by the PDF; sanitize any derivative HTML for UI display. Prefer static page images for preview. Keep output schema/ID validation and lease/revision fencing, but do not mistake them for semantic truth.
- **No URL acquisition in first increment**. A future URL fetch is a separate SSRF feature: http(s) only, no credentials, validate all DNS answers and pin/verify connected public peer, reject loopback/private/link-local/metadata/IPv4-mapped addresses, validate every redirect or disable redirects, cap bytes/time/redirects, no cookies/auth headers, sanitize stored URLs. Reject if the fetch implementation cannot guarantee peer checks. User-supplied URL versus admin-configured model endpoint are different trust boundaries.
- Preserve copyright/privacy/retention metadata; an accessible public exam URL is not a redistribution license. Private originals remain deletable with derived artifacts; do not put student or teacher documents into a public evaluation corpus.

## 5. Smallest testable scope and acceptance gate

### Increment A: fidelity carrier, no semantics and no model calls

Inputs: an owner's uploaded PDF (or offline local fixture in the first proof), with optional user-visible title. Not question IDs, taxonomies, repaired text or manually marked diagrams. Output: immutable private original plus an ordered page manifest. At minimum record source ID/owner, original SHA-256/bytes/MIME, total pages, acquisition time/mode, sanitized filename, renderer identity/version, requested DPI, actual pixel dimensions, page ordinal, original PDF page index/rotation/crop box, page image object key/hash and optional raw text-layer artifact/version/status. Original PDF bytes are the authority; text is a non-authoritative derivative. Any later crop/region must reference source hash + original page + coordinates in a documented coordinate system; it must not replace full-page evidence.

Do not store base64 raster pages in existing bank JSON: it conflicts with HTML/bank caps and inflates every envelope. A separately owned source artifact/manifest contract can later be referenced from BankSource; that requires an explicit migration/retention design, not a hidden patch during parent organization work. Reuse the private-storage interface conceptually, not student-submission ownership IDs.

Acceptance tests (new tests to implement later; **not executed here**):

1. Original bytes/hash round-trip exactly; ordered page count matches PDF; all page images have manifest hashes/dimensions and stable original page numbers. DPI/rotation/crop configuration recorded and page re-render reproducible with pinned renderer.
2. Existing text PDF, two-column PDF, scan-only PDF, rotated page, Unicode/math glyphs, chart and geometry fixtures yield complete page previews. Compare visible radicals/powers/fraction bars/chart values/diagram edges to the original visually; do not claim mathematically perfect OCR. Optional text may be empty and reports this without failing visual preservation.
3. Regression comparisons include the reported Huỳnh Thúc Kháng mixed label/options, Tương Bình Hiệp radicals, Hát Môn histogram and Trần Phú radical option; selection is for inspection only, not injected model hints. For general acquisition also process complete fixture documents with answer keys/matrices/variants; no reviewer-selected question page bounds masquerading as automatic detection.
4. Reject oversize bytes/pages/pixels, huge media boxes, malformed/truncated PDFs, encrypted files and timeout cases with bounded resources; no partially published manifest or orphan artifacts. Cancel/crash/retry is idempotent, does not overwrite an existing original or leak worker paths/secrets.
5. Two-account ownership and leaked-key reads fail; login changes never display prior owner's pages; source deletion handles both original and derivatives. Filename traversal, MIME spoofing, active links and instruction-bearing PDFs cannot fetch/execute anything.
6. Existing HTML-native bank extraction/confirmation/organization behavior remains unchanged. **No automatic question grouping, no manual taxonomy and no prepared semantic annotations** are required by this increment.

### Increment B: separately gated multimodal acquisition experiment

Only after A and explicit authorization: verify the selected provider's documented image support; use a local transport stub first to assert that ordered data-URI image parts (not HTML image strings) and source/page IDs reach the call, with a total image/token/cost cap and no silent retries that exceed the approved budget. Existing model transport can attempt three calls with 120-second per-attempt timeouts ([model limits](</home/dsh/trangchugiaovien/lib/server/model.ts#L61-L64>)); reuse requires an outer deadline and explicit budget, not assuming `maxDuration` is a total cost limit.

AI may propose transcription/regions/question dependencies based on the raw page evidence, with uncertainty and original-page links. Unknown or unsupported vision is a visible blocked capability, never fictional OCR. Require every produced item to reference original source/page(s); validate region bounds, all-page coverage and no invented chart values. Full-page references preserve provenance but are not proof that every dependent figure was correctly attached; no automatic acceptance based only on a reference existing. Keep exact text preservation, OCR fidelity and semantic organization as separate report dimensions. No source gold, hand-repaired formulas, manual question boundaries, answer keys (unless explicitly requested) or taxonomy in model prompts.

## 6. Evidence against scope expansion / unknowns

- Broad PDF ingestion combines parsing/security, storage/retention, rendering, OCR, image-provider capability and segmentation. Current code only proves image transport and text/HTML bank processing; folding all of that into the parent's bounded organization fix would obscure what improved and introduce unrelated production risk.
- Full-page raster evidence alone does not yield editable equations or clean question crops. Higher resolutions improve some glyph readability at substantial memory/cost; proposed caps may exclude large documents and must report that explicitly.
- Current provider/model image capability, deployed renderer/version/isolation, proxy body/auth controls, storage quota/retention policy, and acceptable OCR latency/cost remain unknown. No numerical performance or OCR accuracy claim is justified by this static assessment.
- No reason was found to add manual grouping/taxonomy tools as a prerequisite. They would change the autonomous task and risk hiding acquisition failures instead of preserving evidence.

**Actionable handoff:** finish and evaluate the bounded organization correction against supplied inputs; label upstream PDF losses separately. Then specify Increment A as a small source-fidelity carrier with the above security/acceptance gate. Defer model-enabled PDF extraction, URL import and product-wide import UI until original bytes/pages and ownership can be proven safe and the configured image capability is established.
